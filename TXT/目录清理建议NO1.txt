项目目录整理建议
检查日期：2026-11-09

检查对象：当前工作区根目录、Git 跟踪/未跟踪状态、.gitignore 和 README 路径引用。没有打开 .env、数据库、日志或用户上传文件内容；没有删除、移动或修改任何项目文件。

判断原则

“多余”分成两类：本机缓存/构建产物，可以在确认进程不使用后清理；兼容入口、演示语料、历史评测和个人数据，即使看起来重复，也可能有用途，不应直接删除。

可作为本机清理候选

1. `.venv/` 和 `.venv-demo/`：两个 Python 环境，通常不应放入版本库。若确定 `.venv-demo` 不再用于演示或隔离验证，可删除并按 requirements 重建；保留常用的一个即可。
2. `.pytest_cache/`、根目录及子目录 `__pycache__/`、`*.pyc`：测试和 Python 自动生成缓存，删除安全，后续会重建。
3. `.idea/`、`.claude/`、`.workbuddy/`：本地 IDE/工具状态目录。`.idea/` 已被忽略；另两个目前显示为未跟踪或本地状态，先检查是否有自己写的配置、工作流或提示文件。若纯属生成缓存且不再使用，可本地移除；若团队依赖则应保留并决定是否纳入版本控制。
4. 根目录 `dev_agent.db`：本地 SQLite 数据库，不应提交；仅当确认其中没有需要保留的账号、会话或调试数据后，才可删除。删除会丢失本机数据。
5. `evaluation/results/` 与 `test/evaluation_results/` 中的带时间戳 JSON/TXT：历史实验报告，不是运行程序必需文件。若报告已备份或不再用于对比，可归档到单独目录或清理旧版本；README 和 evaluation/README 明确引用这些报告，所以建议保留最新基线报告。
6. `TXT/` 中反复生成的评估结果与多版分析/对话记录：如果只需要最新结论，可人工归档旧版本；不要批量删除，因为这些文件可能是你要求保留的项目记录。当前仓库跟踪了部分 TXT，同时另有未跟踪 TXT。

看起来重复，但暂不建议删

- `knowledge_base/` 与 `demo_data/knowledge_base/`：内容看起来重叠，但 README 把后者作为随仓库提供的演示语料，生成脚本仍使用前者作为本地默认/旧目录；`.env` 可能把运行目录指向其中之一。本次没有读取 `.env`，所以无法判断根目录知识库是否被当前运行配置使用。确认 `KNOWLEDGE_DIR` 后再决定是否迁移或清理。
- `app.py`、`main.py`：README 明确称为兼容入口，并推荐 `uvicorn app.main:app`。只有在确认没有部署脚本、IDE 配置或外部命令导入它们时，才考虑移除。
- `app/`、`api/`、`agent/`、`auth/` 等目录：承担实际应用功能，不属于重复副本。
- `integrations/mcp/node/package-lock.json`、`frontend/package-lock.json`：分别锁定 MCP Server 与前端依赖，属于可复现安装所需文件，不要当作垃圾文件。
- `demo_data/knowledge_base/.originals/` 和 `documents/`：看起来是文档管理功能产生的上传原件和解析文本，可能包含个人/企业资料；保留前先确认用途与敏感性。删除会破坏文档记录或检索内容。
- `logs/` 下除日志配置外的运行脚本/输出：先核对是否是演示脚本或评估结果；不要因为目录名叫 logs 就整目录清空。
- `.mcp.json`：被忽略且 README 说明是 IDE 本地 MCP 配置样例；不参与应用运行。若没有 IDE 用途可删除本机副本，但不要提交个人连接配置。

当前忽略规则中建议补充的常见本地项

`.pytest_cache/`、`**/__pycache__/`、`*.py[cod]`、`evaluation/results/`（若不打算跟踪评测产物）、测试结果目录、`.env.*`（同时保留 `.env.example`），以及仅在确认不需要共享后忽略 `.workbuddy/` 和 `.claude/`。当前 `.gitignore` 已忽略 `.idea/`、虚拟环境、`.env`、日志、数据库、前端构建产物、MCP node_modules 和 mcp_workspace。

我的建议

最值得先清理的是缓存，而不是业务目录：关闭开发服务后可清 `.pytest_cache`、`__pycache__`；虚拟环境只留一个；旧评测报告按版本归档。根目录 `knowledge_base`、SQLite 数据库和上传文档先确认仍不需要后再动。不要删除被 Git 跟踪的源代码、评测集、README 引用的兼容入口或依赖锁文件。

本次只做了目录和引用检查，没有删除/移动/编辑已有文件；此建议文件为唯一新建文件。未读取 `.env` 或任何数据库、日志、上传资料内容。
